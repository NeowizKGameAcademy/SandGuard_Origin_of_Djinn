# SandGuard 스킬 구매 · 장착 모듈

게임의 플레이어, 타워, 적이 없어도 구매와 장착을 시험할 수 있는 독립 모듈입니다. 원본 프로젝트에는 적용하지 않았습니다. `Assets/SkillTree` 폴더를 프로젝트로 가져오면 됩니다.

## 처음 실행하기

1. ZIP 압축을 풉니다.
2. 압축 안의 **Assets/SkillTree 폴더와 SkillTree.meta**를 Unity 프로젝트의 **Assets** 아래로 복사합니다. 같은 이름의 폴더가 이미 있다면 먼저 기존 내용을 확인하세요.
3. Unity에서 컴파일이 끝나면 상단 메뉴 **SandGuard → Skills → Create Standalone Test Scene**을 누릅니다. 열려 있던 씬에 수정 사항이 있으면 저장 여부를 묻습니다.
4. Play를 누릅니다. Game 화면은 가로 1,000픽셀 이상을 권장합니다.
5. **대시 구매 → 상세 / 장착 선택 → Shift의 선택 스킬 넣기 → 사용 시험** 순서로 누릅니다.
6. 결과에 `Demo cast: move.dash`가 표시됩니다. 3초 안에 다시 사용하면 `Cooldown`이 표시됩니다.

씬에 적이나 플레이어를 넣을 필요가 없습니다. 현재 화면은 기능 확인용이며, 사용 시험은 실행 기록을 표시합니다. 실제 캐릭터 이동이나 공격 이펙트는 발생하지 않습니다. 키보드 입력도 자동으로 연결하지 않습니다.

## 구현된 규칙

- 이동 / 공격 / 타워를 별도 계열로 표시합니다.
- 레벨 제한은 없습니다. 포인트가 충분하고 지정된 선행 스킬을 **모두** 구매하면 상위 스킬을 구매할 수 있습니다.
- 구매하면 포인트를 한 번 차감합니다. 중복 구매, 포인트 부족, 선행 미충족은 상태를 바꾸지 않습니다.
- 액티브 스킬은 구매 후 슬롯에 넣어야 사용할 수 있습니다. Q / E / R / Shift / Space를 제공합니다.
- 스킬마다 허용 슬롯을 지정합니다. 동일 스킬을 여러 슬롯에 중복 장착할 수 없습니다. 다른 슬롯으로 옮길 때는 기존 슬롯에서 빼고 넣습니다.
- 패시브와 시설 해금은 슬롯을 차지하지 않습니다. 실제 효과 적용은 게임 연결부에서 처리합니다.
- 구매·장착 잠금, 보상 포인트 추가, 새 게임 초기화, 상태 스냅샷과 검증 후 복원을 제공합니다.
- 기본 테스트 실행기는 스킬 ID별로 쿨다운을 보관하므로 슬롯 변경으로 쿨다운을 초기화하지 않습니다.
- F는 상호작용 키로 남겨 둡니다.

샘플에는 이동 3개(대시·더블 점프·흔적 귀환), 공격 4개, 타워 해금 3개가 들어 있습니다. 비용과 선행 관계는 기능 확인용 제안 값입니다. 확정된 밸런스나 스킬 효과 구현은 아닙니다.

## 스킬 추가와 비용 수정

**SandGuard → Skills → Create Demo Tree Asset**으로 데이터 파일을 만듭니다. 씬의 `SkillTree Standalone Test`를 선택하고 `Definition`에 이 파일을 넣습니다.

Inspector의 각 Nodes 항목에서 다음을 수정합니다.

| 항목 | 의미 |
|---|---|
| Id | 연결에 사용하는 고유 이름. 예: `move.dash` |
| Display Name / Description | 화면 이름과 설명 |
| Branch | 이동, 공격, 타워 계열 |
| Kind | Active는 장착 후 사용, Passive는 해금 상태로 조회 |
| Cost | 필요한 포인트 |
| Prerequisites | 선행 스킬의 Id. 여러 개면 모두 필요 |
| Allowed Slots | 액티브의 장착 가능 키. 패시브는 비움 |

**선행 관계 / ID / 슬롯 검사** 버튼으로 중복 ID, 없는 선행 스킬, 순환 연결 등을 검사합니다. 데이터는 Play 시작 시 읽으므로 수정 후 Play를 다시 시작하세요.

## 다른 팀원의 기능 연결하기

구매·장착 정보를 관리하는 중심은 `SkillTreeSession.Service`입니다. UI는 이것을 읽고 명령을 보내는 별도 컴포넌트이므로 나중에 Canvas UI로 교체할 수 있습니다.

### 1. 레벨업 포인트

레벨업을 처리하는 컴포넌트에서 보상이 확정되면 `session.GrantPoints(보상량)`을 한 번 호출합니다. 레벨별 보상량 증가는 기존 성장 테이블에서 정하면 됩니다. 구매는 이 모듈의 Points를 사용합니다.

현재 프로젝트의 `PlayerProgression.SkillPoints`와 이 모듈은 자동 연결되지 않습니다. 통합 시 **포인트 지갑의 소유자를 하나로 정해야 합니다**. 이 모듈을 사용할 경우 기존 HUD도 `Service.Points`를 읽도록 바꾸고, 기존 `TrySpendSkillPoints`로 이중 차감하지 마세요. 기존 지갑을 유지하려면 별도의 지갑 어댑터 작업이 필요합니다. 같은 레벨업 이벤트를 여러 번 구독하면 보상도 여러 번 지급되므로 구독 해제와 중복 지급 방지는 연결부 책임입니다.

### 2. 실제 공격·이동 실행

팀원의 컴포넌트를 호출하는 MonoBehaviour를 만들고 `ISkillExecutor`를 구현합니다.

```csharp
public bool TryExecute(string skillId, out string reason)
```

이 메서드에서 ID에 맞는 기능을 선택하고, 생존 여부·마나·쿨다운 등 실행 조건을 검사한 뒤 실제 기능을 호출합니다. 성공하면 true, 실행하지 못하면 false와 이유를 반환합니다. 만든 컴포넌트를 Session의 **Executor Source**에 넣으면 데모 실행기를 대체합니다. 초기화는 Play 시작 시 이루어집니다.

입력 담당 컴포넌트에서 Q는 `session.UseQ()`, E는 `UseE()`, R은 `UseR()`, Shift는 `UseShift()`, Space의 추가 공중 점프는 `UseSpace()`를 호출합니다. 키를 눌렀을 때마다 현재 장착된 스킬 ID가 실행기에 전달됩니다.

현재 `PlayerSkillCaster`는 Q/E/R과 공격 인덱스가 고정되어 있으므로 통합할 때 기존 고정 입력을 이 경로로 교체해야 합니다. 기존 입력과 새 입력을 동시에 호출하면 중복 시전할 수 있습니다. 쿨다운·마나 처리는 실제 실행기가 계속 담당하며, 장착 변경 시 초기화하면 안 됩니다. 기본 지상 점프는 기존 이동기에서 유지하고, Space 슬롯은 추가 점프 조건을 검사할 때만 사용하세요.

### 3. 타워 해금과 패시브

타워 메뉴에서 `session.Service.IsLearned("tower.cobra")`처럼 해금 여부를 조회할 수 있습니다. Session의 `onChanged` 또는 Service의 `Changed`를 구독하면 UI를 갱신할 수 있습니다.

스탯을 바꾸는 패시브는 구매·복원·초기화 후 스냅샷을 비교해 추가와 제거를 처리하는 연결부가 필요합니다. 이벤트가 올 때마다 효과를 무조건 더하면 중첩됩니다. 장착 전용 이동 능력을 `PlayerStarterEffects`가 미리 켜고 있다면 통합 시 그 테스트 설정도 함께 정리해야 합니다.

## 개발 계약과 범위

- Core는 Unity 의존성이 없는 순수 C#입니다. Runtime은 ScriptableObject·세션·기능 시험 화면, Editor는 생성 메뉴를 담당합니다. 프로젝트의 다른 게임 어셈블리를 참조하지 않습니다.
- Service는 Unity 메인 스레드 등 단일 스레드에서 사용합니다.
- Changed는 구매·장착 상태 반영 후 호출됩니다. 알림 중 다시 변경 명령을 호출하면 Busy로 거부합니다. 알림에서 직접 연쇄 구매하지 말고 다음 프레임에 호출하세요.
- 알림 수신자가 예외를 던져도 이미 반영된 구매는 취소하지 않으며 다른 수신자에게 계속 알립니다. 따라서 외부 효과까지 포함하는 원자적 구매 트랜잭션은 제공하지 않습니다.
- 기존 프로젝트의 `ISkillTreeCommands` / `ISkillTreeReader`를 직접 구현하지 않습니다. 기존 인터페이스의 재진입 처리·효과 적용 순서 계약에 맞춘 어댑터는 통합 단계에서 추가해야 합니다.
- Snapshot / Restore는 메모리 상태 API입니다. 디스크 저장·버전 마이그레이션·서버 검증은 포함하지 않습니다. Restore와 Reset은 편집 잠금을 우회하므로 신뢰할 수 있는 저장/게임 시작 코드만 호출하세요.
- 레벨 보상 증가, 실제 이동·공격·타워 효과, 최종 그래픽 스킬 트리, 게임 입력 연결은 이번 독립 모듈에 포함하지 않습니다.

## 검증

`TEST_RESULTS.txt`에 실제 실행 결과가 있습니다. 순수 C# 테스트는 .NET 8 SDK가 있는 환경에서 `dotnet run --project Tests/SkillTests.csproj`로 재실행할 수 있습니다. Unity의 테스트 패널에서는 잠금·구매·장착·사용 시험을 직접 확인할 수 있습니다.

Unity 6000.2.8f1 참조 라이브러리로 컴파일을 검사했습니다. 실제 Unity Editor 가져오기와 Play Mode 화면 검증은 수행하지 않았습니다.
