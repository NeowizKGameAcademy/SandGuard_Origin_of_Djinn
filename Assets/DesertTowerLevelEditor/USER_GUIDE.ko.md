# Desert Tower 레벨 에디터 사용 설명서

**대상: 레벨 제작자 · 에디터 0.2.0 · Unity 6000.2.8f1 · 작성일 2026-09-05**

이 설명서는 현재 구현된 기능을 기준으로 작성했습니다. 메뉴는 영어, 전용 편집 창의 버튼은 한글 이름을 함께 사용합니다. Unity의 언어 설정에 따라 Terrain 도구 이름은 다르게 보일 수 있습니다.

처음 사용한다면 **1장 → 2장 → 12장 실습** 순서로 진행하세요. 직접 새 맵을 만들 때는 **3장부터 11장까지** 순서대로 따라 하면 됩니다.

## 1. 먼저 알아둘 것

### 맵은 세 종류의 정보로 구성됩니다

| 구분 | 예 | 만드는 방법 |
|---|---|---|
| 실제 공간 | 모래 지면, 산, 절벽, 성벽, 경사로 | Terrain·메시·환경 프리팹 배치 |
| 배치 정보 | 코어 위치, 적 출현 위치, 초기 타워 위치 | 마커 배치 |
| 진행 정보 | 설치 구역, 경로 가이드, 웨이브 | 영역과 데이터 설정 |

**마커를 배치하는 것과 실제 게임 오브젝트를 생성하는 것은 별개입니다.** 코어 마커를 놓으면 코어 위치를 저장합니다. 체력·피격·패배 처리까지 생기지는 않습니다. 게임 코드가 이 데이터를 읽어 실제 코어·적·타워를 생성하도록 연결하는 구조입니다.

현재 Play 테스트는 임시 모형으로 이동과 공간을 확인합니다. EnemyAI의 전투 판단, 타워 공격, 바리케이드 파괴, 마나, 성장, 승패는 별도 게임 구현 범위입니다.

### 창 이름

| Unity 창 | 하는 일 |
|---|---|
| **Scene** | 맵을 보고 클릭·배치하는 작업 화면 |
| **Hierarchy** | 현재 장면에 놓인 오브젝트 목록 |
| **Project** | 모델·프리팹·재질·데이터 등 파일 목록 |
| **Inspector** | 선택한 오브젝트나 파일의 세부 설정 |
| **Game** | Play 모드에서 실행 화면 확인 |
| **Desert Tower** | 이번에 만든 전용 레벨 편집 창 |

### 레벨 루트

레벨 루트는 **이 맵에 속하는 지형과 마커를 묶는 최상위 오브젝트**입니다. `LevelRoot` 컴포넌트가 붙어 있습니다.

클릭 배치와 이동 영역 굽기는 선택한 루트의 자식 오브젝트를 기준으로 작동합니다. 밖에서 가져온 Terrain·바위·벽도 **Hierarchy에서 레벨 루트 아래로 옮겨 주세요.** 이동 가능한 표면이나 막는 구조에는 Collider가 필요합니다.

첫 작업에서는 레벨 루트의 Position·Rotation을 0, Scale을 1로 유지하면 다루기 쉽습니다. 특히 루트와 마커·영역의 Scale은 `(1, 1, 1)`로 유지하세요.

## 2. 에디터 열기와 레벨 시작

### 기존 예제로 시작하기

1. Unity에서 DesertTower 프로젝트를 엽니다.
2. 상단 **Tools → Desert Tower → Level Editor**를 선택합니다.
3. 전용 창 상단의 **요새 예제** 또는 **협곡 예제**를 누릅니다.
4. 기존 장면을 수정한 상태라면 Unity 저장 안내에 따라 처리합니다.
5. 새 예제가 생성되면 **전체 보기**로 맵을 확인합니다.

예제 버튼은 **새 예제 장면을 생성**합니다. 이미 편집하던 예제를 다시 열려면 Project의 `Assets/DesertTowerLevels/Scenes`에서 해당 `.unity` 파일을 더블클릭하세요.

### 빈 장면에서 시작하기

1. Unity의 **File → New Scene**에서 새 장면을 만듭니다. 처음에는 카메라와 조명이 있는 기본 장면을 사용해도 됩니다.
2. 전용 창에서 **새 레벨 루트**를 누릅니다.
3. 상단 **편집 레벨**에 방금 만든 루트가 지정됐는지 확인합니다.
4. **지형 / 환경 → Terrain 만들기**를 누릅니다.
5. 장면을 원하는 이름으로 저장합니다. 예: `Canyon_MyLevel.unity`.

**새 레벨 루트는 현재 장면에 루트를 추가하는 버튼**입니다. 장면 자체를 새로 만들거나 기존 오브젝트를 지우지는 않습니다.

### 다섯 탭

| 탭 | 작업 |
|---|---|
| 지형 / 환경 | Terrain 선택, 블록·길·프리팹 배치 |
| 마커 | 코어·스폰·시작점·시설 위치 지정 |
| 구역 / 경로 | 설치 영역, 전투 영역, 진격 가이드 지정 |
| 웨이브 | 스폰·목표·출현 수·시간 설정 |
| 검사 / 저장 | 이동 영역 굽기, 오류 확인, Play 테스트, 저장 |

### 공통 조작

| 입력 | 기능 |
|---|---|
| Scene 왼쪽 클릭 | 현재 선택한 배치 도구 사용 |
| Q / E | 배치 중 방향을 15도씩 회전 |
| Esc / **선택 모드** | 배치 도구 종료 |
| Backspace | 아직 완성하지 않은 영역·길의 마지막 점 삭제 |
| Ctrl+Z / Ctrl+Y | 완료된 편집 작업 되돌리기 / 다시 실행 |
| 선택 모드에서 Unity 이동·회전 도구 | 배치한 오브젝트의 위치·방향 조정 |
| Hierarchy 선택 후 Delete | 선택한 오브젝트 삭제 |

상단 **격자 정렬**을 켜면 X·Z 위치가 입력한 간격에 맞춰집니다. 첫 작업에는 1m가 편합니다. 바위처럼 불규칙하게 놓을 물체는 필요에 따라 끄세요. Scene의 **Gizmos**를 켜야 마커와 구역 표시를 볼 수 있습니다.

## 3. 산·협곡 지형 만들기

### 3-1. Terrain 생성

**지형 / 환경 → Terrain 만들기**를 누르면 레벨 루트 아래에 `Landscape`가 생깁니다. 기본 크기는 **96×96m**, 높이 범위는 **24m**, 높이맵 해상도는 **257**입니다. 바닥은 평평한 상태로 시작합니다. 자동으로 텍스처가 칠해지지는 않습니다.

**Terrain 편집하기**를 누르면 루트 안의 Terrain을 선택합니다. Terrain이 여러 개라면 Hierarchy에서 편집할 것을 직접 선택하세요.

### 3-2. 큰 산세 만들기

1. Terrain을 선택하고 Inspector에서 **Paint Terrain** 도구를 엽니다.
2. **Raise or Lower Terrain**을 선택합니다.
3. 브러시 크기를 크게 잡고 맵 외곽과 중앙의 산줄기를 올립니다.
4. 낮출 부분은 같은 도구에서 **Shift를 누른 채 드래그**합니다.
5. 작은 요철보다 **두 진입로·중앙 분지·코어 공간이 어디인지** 먼저 보이도록 만듭니다.

높이 올리기·낮추기의 기본 입력은 [Unity Terrain 높이 도구 안내](https://docs.unity3d.com/kr/6000.0/Manual/terrain-RaiseLowerTerrain.html)에서 확인할 수 있습니다.

처음부터 바닥을 파서 골짜기를 만들고 싶다면 새 Terrain 전체를 약간 올린 뒤 작업하세요. 기본 바닥 높이보다 아래로 계속 파는 방식에는 제한이 있습니다. 전체 평탄화는 맵을 처음 만들 때 사용하고, 이미 만든 산세에는 부분 브러시를 사용하세요.

### 3-3. 방어 공간을 평평하게 만들기

1. **Set Height**를 선택합니다.
2. 기준 높이를 설정합니다. 예: 낮은 길 2m, 높은 방어 구역 5m.
3. 서측 방어 공간, 동측 고지, 중앙 분지, 코어 주변을 각각 칠합니다.
4. **Smooth Height**로 경계 부분을 부드럽게 연결합니다.
5. 높은 구역까지 걸어 올라갈 수 있는 넓은 경사 구간을 만듭니다.

Terrain의 위치와 도구의 Local/World 설정에 따라 수치의 기준이 달라질 수 있습니다. 이 설명서의 2m·5m 예시는 Terrain의 Y가 0인 경우입니다. 평탄화와 경계 다듬기는 [Set Height](https://docs.unity3d.com/6000.0/Documentation/Manual/terrain-SetHeight.html), [Smooth Height](https://docs.unity3d.com/6000.0/Documentation/Manual/terrain-SmoothHeight.html)를 참고하세요.

방어 구역은 바리케이드만 들어갈 폭으로 만들지 말고, 타워와 플레이어가 옆에 설 여유도 남기세요. 첫 실험값으로 진입로 폭 6~8m, 방어 공간 8×8m, 중앙 분지 폭 약 20m부터 확인할 수 있습니다. 확정된 밸런스 수치는 아닙니다.

### 3-4. 모래·암반 텍스처 칠하기

1. 사용할 모래·암반 텍스처를 Unity Project에 넣습니다.
2. Terrain의 **Paint Terrain → Paint Texture**를 선택합니다.
3. **Edit Terrain Layers → Create Layer**로 텍스처를 사용하는 레이어를 만듭니다. 이미 있는 TerrainLayer를 쓰려면 **Add Layer**로 추가합니다.
4. 모래 레이어로 길과 분지를, 암반 레이어로 산비탈을 칠합니다.
5. TerrainLayer의 타일 크기를 조정해 무늬가 지나치게 크거나 작지 않도록 합니다.

Terrain 표면은 일반 Material을 바닥에 드래그하는 방식과 다릅니다. [Unity Paint Texture 안내](https://docs.unity3d.com/6000.0/Documentation/Manual/terrain-PaintTexture.html)를 기준으로 TerrainLayer를 사용하세요.

협곡 예제에는 `Sand surface`, `Rock surface` 레이어가 이미 준비되어 있습니다. 텍스처는 예제용이므로 원하는 아트 자산으로 바꿀 수 있습니다. **모래를 칠했다고 적의 이동 경로나 설치 가능 구역이 자동 생성되지는 않습니다.**

### 3-5. 수직 절벽은 프리팹으로 보완

Terrain으로 큰 산세를 만든 뒤 절벽·암봉·바위 프리팹을 추가하면 됩니다. 돌출된 절벽이나 아치 같은 형태는 별도 메시를 사용하세요. 배치 방법은 5장에서 설명합니다.

### 3-6. 적이 이동할 수 있는 지형 경사로 만들기

**지형을 항상 평평하게 만들 필요는 없습니다.** Terrain으로 만든 오르막·내리막도 이동 가능한 공간으로 구울 수 있습니다. 별도 경사로 프리팹 없이 산길이나 고지로 이어지는 비탈을 만들 수 있습니다.

현재 DesertTower 프로젝트의 기본 에이전트 설정은 다음과 같습니다. 이 값은 프로젝트의 이동 영역 생성 기준이며, 적의 전투 능력치가 아닙니다.

| 항목 | 현재 값 | 의미 |
|---|---:|---|
| 최대 경사 | 45도 | 이동 영역 생성 시 허용하는 경사의 기준 |
| 최대 단차 | 0.75m | 연결 가능한 계단·턱 높이의 기준 |
| 에이전트 반경 | 0.5m | 길 가장자리와 장애물에서 확보할 여유를 계산하는 기준 |
| 에이전트 높이 | 2m | 통과에 필요한 위쪽 공간의 기준 |

위 값은 이 프로젝트의 기본 설정입니다. 패키지를 다른 프로젝트로 가져가거나 NavMeshSurface의 에이전트 종류를 바꾸면 기준이 달라질 수 있습니다. **45도 이하라는 이유만으로 통과가 보장되지는 않습니다.** 길 폭, 국소적인 굴곡, 장애물, 이동 영역 생성 해상도에 따라 연결이 끊길 수 있습니다. 반경의 두 배인 1m 역시 안전하게 통과할 수 있는 길 폭을 보장하는 값은 아닙니다.

#### 제작과 확인 순서

1. 낮은 길과 높은 구역 사이에 충분히 긴 비탈을 만듭니다. 예를 들어 높이 차이가 3m라면 수평 거리 9m 정도에 걸쳐 올라가도록 시작해 볼 수 있습니다.
2. **Smooth Height**로 비탈의 시작·끝과 중간의 급격한 굴곡을 다듬습니다. 길 옆 절벽까지 과하게 평탄화하지 않도록 브러시 범위를 조절하세요.
3. Terrain이 **LevelRoot의 하위 오브젝트**인지, 활성화된 **Terrain Collider**가 있는지 확인합니다. 현재 에디터는 루트 아래의 콜라이더를 기준으로 이동 영역을 만듭니다.
4. **검사 / 저장** 탭에서 이동 영역 굽기를 실행합니다.
5. Scene에서 NavMesh 표시를 켜고 낮은 길부터 높은 구역까지 이동 가능 영역이 이어지는지 확인합니다. 끊기는 곳은 비탈을 완만하게 하거나 길을 넓히고 장애물을 조정한 뒤 다시 굽습니다.
6. 진단 도구를 설치한 경우 스폰과 목표를 경사로 양쪽에 지정해 이동 테스트를 합니다. 실제 게임에서도 EnemyAI와 사용하는 적 프리팹으로 통과를 확인하세요.

**지형 높이·경사·콜라이더 배치를 수정한 뒤에는 이동 영역을 다시 구워야 합니다.** 경로 가이드의 점을 경사로 위에 놓는 것만으로 이동할 수 없는 지형이 통과 가능해지지는 않습니다.

에디터는 이동 가능한 공간과 스폰·목표·경로 데이터를 제공합니다. 실제 게임에서 적이 경로를 따라 움직이고, 회전하고, 장애물에 대응하는 동작은 **EnemyAI 등 게임의 이동 시스템**이 담당합니다. 에디터의 진단 이동 성공은 공간 연결을 확인하는 결과이며, 실제 적의 전투 행동까지 검증하는 것은 아닙니다.

## 4. 바닥·벽·단상·경사로 만들기

### 블록으로 공간 구성하기

1. **지형 / 환경 → 바닥 · 벽 · 단상**으로 이동합니다.
2. **폭 / 높이 / 길이 (m)**를 설정합니다.
3. **표면 재질**에 사용할 Material을 넣습니다. 비워 두면 기본 사암색 재질을 사용합니다.
4. **회전 Y**를 설정하거나 배치 중 Q/E로 방향을 바꿉니다.
5. **블록 클릭 배치**를 누르고 Scene의 지면을 클릭합니다.
6. 필요한 만큼 반복한 뒤 Esc를 누릅니다.

| 예시 | 폭 X | 높이 Y | 길이 Z |
|---|---:|---:|---:|
| 작은 단상 | 8 | 1 | 8 |
| 벽 | 2 | 4 | 8 |
| 높은 방어대 | 12 | 3 | 12 |

블록의 밑면이 클릭한 지면에 놓입니다. 생성 후에는 Hierarchy에서 선택해 Transform으로 수정할 수 있습니다. **표면 재질** 필드는 앞으로 생성할 블록·길에 적용되며, 기존 오브젝트 전체의 재질을 한 번에 바꾸지는 않습니다.

### 길·경사로 메시 만들기

1. **길 폭 (m)**을 설정합니다. 처음에는 6m 정도로 시작합니다.
2. **지면 위 간격**을 설정합니다. 기본값은 약 0.03m입니다.
3. **길 점 찍기**를 누릅니다.
4. Scene에서 길의 시작과 다음 위치를 순서대로 클릭합니다. 최소 2점이 필요합니다.
5. **길 생성 (…점)**을 누릅니다.

같은 높이의 점은 평평한 길을, 높이가 다른 점은 경사로를 만듭니다. 점은 실제 Collider가 있는 표면에 찍습니다. 허공의 좌표를 직접 입력해 점을 생성하는 도구는 아닙니다.

**이 도구는 지형 위에 충돌 가능한 메시를 연결합니다. Terrain을 자동으로 깎거나 텍스처를 칠하지 않습니다.** 산을 관통하면 Terrain을 먼저 다듬고, 급한 코너에서는 폭이 겹치지 않는지 확인하세요.

생성 후 길의 원래 점들을 다시 편집하는 전용 기능은 없습니다. 모양을 바꾸려면 Undo 또는 기존 길 삭제 후 다시 생성합니다. 메시 파일은 별도 자산으로 저장되므로 장면에서 길을 삭제해도 파일이 자동 삭제되지는 않습니다.

## 5. 환경 프리팹 추가와 배치

### 5-1. 모델을 프리팹으로 준비하기

이미 `.prefab` 자산이 있다면 5-2로 넘어갑니다. 블렌더 등에서 만든 모델은 다음 순서로 준비하세요.

1. 모델과 텍스처 파일을 Project의 원하는 폴더에 넣습니다. 예: `Assets/MyLevelAssets/Models`.
2. 모델을 Scene에 놓고 크기와 재질을 확인합니다.
3. 빈 부모 오브젝트를 만들고 모델을 자식으로 넣습니다. 예: `Cliff_A` 아래에 모델 배치.
4. 부모의 원점을 **지면에 닿을 기준점**으로 정하고, 자식 모델의 위치를 맞춥니다.
5. 길을 막거나 올라설 물체에는 Collider를 추가합니다. 단순한 형태는 BoxCollider, 복잡한 고정 지형은 적절한 MeshCollider 등을 사용할 수 있습니다.
6. 부모 오브젝트를 Project의 `Assets/MyLevelAssets/Prefabs` 같은 폴더로 드래그해 프리팹으로 저장합니다.

프리팹 생성은 [Unity 기본 프리팹 만들기](https://docs.unity3d.com/6000.0/Documentation/Manual/CreatingPrefabs.html)와 같은 절차입니다. 부모의 Scale을 1로 정리해 두면 배치 후 크기를 다루기 편합니다.

### 5-2. 에디터에서 반복 배치하기

1. **지형 / 환경 → 구조물 · 절벽 자산**으로 이동합니다.
2. Project의 프리팹을 **배치할 프리팹** 필드에 드래그합니다.
3. **프리팹 클릭 배치**를 누릅니다.
4. Scene의 지면을 클릭합니다. 계속 클릭하면 같은 프리팹을 반복 배치합니다.
5. Q/E로 Y 방향을 바꿉니다. Esc로 끝냅니다.
6. 선택 모드에서 각각의 위치·회전·크기를 조정합니다.

배치 기준은 **프리팹의 원점**입니다. 프리팹의 원점이 중앙에 있으면 아래쪽이 지면에 묻힐 수 있습니다. 프리팹을 준비할 때 원점을 정리하거나, 배치 후 Y 위치를 수정하세요. 경사면의 법선에 맞춰 자동으로 기울어지거나 크기가 무작위로 바뀌는 기능은 없습니다.

별도의 프리팹 팔레트 등록 과정은 없습니다. 사용할 프리팹을 필드에 넣고 배치하면 됩니다. 모델과 Collider·재질을 묶은 프리팹을 사용하면 이후 수정이 쉽습니다.

### 5-3. 환경 프리팹과 시설 마커의 차이

| 배치하려는 것 | 사용할 방식 |
|---|---|
| 바위·절벽·성벽·기둥·장식 | **프리팹 클릭 배치**로 실제 환경 오브젝트 배치 |
| 코어·적의 출현 위치 | **마커** 탭에서 해당 종류 배치 |
| 시작부터 존재할 코브라 타워·소환 타워 | **초기 시설** 마커 + 요소 정의 |
| 플레이어가 나중에 건설할 공간 | **설치 가능 구역** 지정 |

환경 프리팹은 실제 오브젝트로 들어오므로 그 프리팹에 붙은 컴포넌트도 함께 들어옵니다. 반면 시설 마커는 위치 데이터이며, 현재 도구가 해당 시설의 게임 스크립트를 자동 생성하지 않습니다.

## 6. 마커 종류와 배치

### 사용할 수 있는 마커

| 화면 이름 | 종류 | 역할 | 첫 맵의 배치 예 |
|---|---|---|---|
| 코어 | Core | 방어 목표 위치 | 최후방에 1개 |
| 적 스폰 | EnemySpawn | 적이 나타날 위치와 반경 | 서문·동문에 각 1개 |
| 플레이어 시작 | PlayerStart | 테스트 플레이어의 시작 위치·방향 | 코어 앞에 1개 |
| 부활 | Respawn | 게임 연결용 부활 위치 | 코어 옆의 여유 공간 |
| 초기 시설 | InitialFacility | 시작 배치할 시설의 위치 | 방어 구역의 타워 예시 |
| 랜드마크 | Landmark | 제작 중 참고할 기준 위치 | 광장 중앙·주요 표식 |

현재 검사에서는 코어와 플레이어 시작점이 각각 정확히 1개 필요합니다. 스폰이 2개 미만이거나 부활 지점이 없으면 기획 기준 경고가 나옵니다. 부활·랜드마크는 위치 정보이며, 자체 부활 로직이나 이벤트를 실행하지 않습니다.

### 배치 순서

1. **마커** 탭에서 **종류**를 선택합니다.
2. 필요하면 **요소 / 표시 정의 (선택)**를 넣습니다. 처음에는 비워도 됩니다.
3. **방향 Y**를 설정합니다.
4. **Scene에서 클릭 배치**를 누른 뒤 바닥을 클릭합니다.
5. Esc를 누르고, 배치된 마커를 선택합니다.
6. Inspector 또는 창의 **선택 항목**에서 Label을 알기 쉽게 바꿉니다. 예: `서문 스폰`, `동문 스폰`, `코어 성소`.

### 주요 설정

| 필드 | 사용 방법 |
|---|---|
| Label | 목록과 Scene에 표시할 이름 |
| Id | 내부 연결용 식별자. 보통 자동 생성된 값을 유지 |
| Definition | 공통 요소 정의. 지정하면 그 정의의 점유 크기·표시 거리를 사용 |
| Footprint | 폭 X·높이 Y·길이 Z. 원점은 바닥이며 박스가 위로 표시됨 |
| Preview Range | 선택 시설의 거리 원 표시. 실제 공격 사거리가 아님 |
| Spawn Radius | 스폰 마커 주변의 출현 반경 |

정의가 지정된 마커의 크기를 바꾸려면 **정의 자산의 Footprint**를 수정하세요. 마커 자체의 Footprint를 바꿔도 정의의 값이 우선합니다. 개별 마커를 다른 크기로 만들려면 정의를 따로 만들거나 Definition을 비웁니다.

지형을 나중에 바꿨다면 마커를 선택하고 **지면에 맞추기**를 누른 뒤 높이를 확인하세요. 위아래 지형이 겹친 곳에서는 원하는 층에 놓였는지 직접 확인합니다.

마커를 복제하면 ID도 복제됩니다. 복제 후 **복제한 마커의 ID 새로 만들기**를 눌러 새 ID를 발급하고, 새 경로·웨이브에 연결하세요. 이미 연결해서 쓰던 마커의 ID를 바꾸면 참조를 다시 지정해야 합니다.

## 7. 타워·적의 요소 정의 만들기

요소 정의는 **게임이 해석할 종류와 에디터 표시 정보를 담은 자산**입니다.

1. Project에서 저장할 폴더를 선택합니다. 예: `Assets/DesertTowerLevels/Data`.
2. 우클릭 **Create → Desert Tower → Level Element**를 선택합니다.
3. 파일 이름을 정합니다. 예: `Cobra_Element`, `Raider_Element`.
4. Inspector에서 아래 값을 설정합니다.

| 필드 | 코브라 예시 | 의미 |
|---|---|---|
| Display Name | 코브라 타워 | 정의의 이름 |
| Game Key | `tower.cobra` | 게임의 자산 목록에서 해석할 키. 제작팀이 이름을 정함 |
| Preview Prefab | 코브라 모델 프리팹 | 편집용 외형 참조 |
| Footprint | `(2, 3, 2)` | 표시·공간 확인용 크기 |
| Preview Range | `8` | 편집용 거리 원 |
| Preview Color | 금색 | 표시 색상 |

**현재 Preview Prefab을 넣어도 마커가 실제 모델로 바뀌지는 않습니다.** 참조를 보관하며, Scene은 박스·아이콘 형태의 Gizmo로, 진단 모듈은 임시 모형으로 표시합니다. Game Key를 넣는 것만으로 프리팹 검색이나 실제 타워 생성이 연결되지도 않습니다. 게임의 생성기에서 키를 해석해야 합니다.

이동 속도·공격력·체력은 이 자산에서 설정하지 않습니다. 강한 적과 일반 적의 서로 다른 전투 능력도 실제 게임 설정에서 관리합니다.

완성한 자산은 초기 시설 마커의 Definition 또는 웨이브 그룹의 **게임 키 / 표시 정의 (선택)**에 넣습니다.

## 8. 설치 구역과 전투 구역 지정

### 세 가지 구역

| 종류 | 효과 |
|---|---|
| 설치 가능 / Buildable | 해당 영역을 건설 허용 영역으로 지정 |
| 설치 금지 / NoBuild | 건설에서 제외할 영역. 설치 가능 구역과 겹치면 금지가 우선 |
| 전투 구역 / Combat | 공간에 이름과 범위를 붙이는 데이터. 전투를 시작하거나 적을 자동 감지하지 않음 |

### 구역 그리기

1. **구역 / 경로** 탭에서 **영역 종류**를 선택합니다.
2. **영역 점 찍기**를 누릅니다.
3. 평평한 바닥의 외곽을 시계 방향 또는 반시계 방향으로 클릭합니다.
4. 최소 3점을 찍습니다. 네 점이면 사각형을 만들 수 있습니다.
5. **영역 완성 (…점)**을 누릅니다. 마지막 점과 첫 점은 자동으로 연결됩니다.
6. 완성한 영역의 Label을 바꿉니다. 예: `서측 설치 구역`.

점 순서를 앞뒤로 넘나들며 찍으면 변이 교차할 수 있습니다. 잘못 찍은 마지막 점은 Backspace로 지우고 다시 찍으세요. 완료된 영역은 선택 후 Scene의 꼭짓점 핸들로 수정합니다.

### 높이가 다른 바닥은 따로 지정

영역은 한 장의 평면입니다. 현재 생성 도구는 첫 점과 다른 점의 높이가 0.5m보다 크게 다르면 생성을 거부합니다. 경사로나 여러 층을 하나의 영역으로 묶지 말고 평탄한 구역별로 만드세요.

**Height는 영역 기준면 위·아래를 합한 높이**입니다. Height가 1이면 기준면에서 위로 0.5m, 아래로 0.5m 범위에 적용됩니다. 예를 들어 Y=5의 고지에 Height=1인 구역을 놓으면 Y=2의 아래층에는 적용되지 않습니다.

### 이 맵에서 배치할 구역

- 서측 저지선: 설치 가능 구역.
- 동측 고지: 별도의 설치 가능 구역.
- 중앙 광장 후방: 최종 방어용 설치 가능 구역.
- 코어와 스폰 출구: 설치 금지 구역.
- 중앙 광장: 전투 구역.

설치 가능 영역을 그리는 것은 지형의 충돌체를 바꾸거나 시설을 자동 배치하는 작업이 아닙니다. 실제 게임에서 건설할 때는 점유 공간·비용 등 추가 판정이 필요합니다.

## 9. 스폰·코어·경로 연결

**스폰과 목표 코어는 필요하지만, 경로 가이드는 선택 사항**입니다. 두 가지 방식 중 하나를 사용합니다.

### A. 스폰과 코어만 지정하기

1. 코어와 적 스폰 마커를 먼저 배치합니다.
2. 웨이브의 출현 그룹에서 **스폰**과 **목표 코어**를 선택합니다.
3. **경로 가이드 (선택)**는 **가이드 없음 (AI가 경로 결정)**으로 둡니다.

게임의 EnemyAI가 목적지까지 경로를 결정하도록 할 때 사용합니다. 현재 진단 모듈에서는 NavMesh를 통해 스폰에서 코어로 이동합니다.

### B. 경유할 구간도 지정하기

1. **구역 / 경로** 탭의 **스폰** 필드에 적 스폰 마커를 넣습니다.
2. **코어** 필드에 목표 코어 마커를 넣습니다. 둘 다 같은 레벨 루트에 속해야 합니다.
3. **진격 경로 만들기**를 누릅니다.
4. 경로의 Label을 `서문 → 광장 → 코어`처럼 바꿉니다.
5. **편집 경로**에 해당 경로가 선택되어 있는지 확인합니다.
6. **경유점 클릭 추가**를 누르고, 적이 지나갈 위치를 스폰 쪽부터 순서대로 클릭합니다.
7. Esc로 종료합니다. Scene에서 경로를 선택해 경유점 핸들을 움직일 수 있습니다.
8. 웨이브 그룹의 **경로 가이드 (선택)**에 이 경로를 지정합니다.

스폰과 코어는 경로의 양 끝에 자동으로 붙습니다. 같은 위치를 경유점으로 다시 찍을 필요는 없습니다. 경유점 삭제·순서 변경은 선택한 경로의 Inspector에 있는 **Waypoints** 목록에서 처리합니다.

주황 점선은 의도한 연결이며 실제 장애물 우회 결과가 아닙니다. **검사 / 저장 → … 실제 경로 표시**를 눌러 청록 실선으로 계산된 이동 경로를 확인하세요. 가이드를 만들었다고 벽을 통과할 수 있는 것은 아닙니다.

경로 가이드를 선택하면 웨이브 그룹의 스폰과 목표도 그 경로의 양 끝에 맞춰집니다. 이후 스폰만 다른 것으로 바꾸면 불일치 오류가 나므로 함께 확인하세요.

기존 0.1 데이터는 `미지정 (기존 경로에서 읽기)`로 표시될 수 있습니다. 유효한 경로가 있으면 정상적으로 연결됩니다. 새 작업에서는 스폰과 목표를 명시적으로 선택하는 편이 확인하기 쉽습니다.

## 10. 웨이브 구성과 레벨에 지정

### 10-1. 웨이브 데이터 만들기

1. 먼저 코어와 적 스폰 마커를 배치합니다.
2. **웨이브** 탭을 엽니다.
3. 데이터가 없다면 **웨이브 데이터 만들기**를 누릅니다.
4. `MyCanyon_Waves.asset`처럼 이름을 정해 저장합니다.
5. 창의 **웨이브 데이터** 필드에 생성한 자산이 연결됐는지 확인합니다.

이미 WaveSet 자산이 있다면 이 필드에 드래그하면 됩니다. **레벨에 어떤 웨이브를 사용할지 지정하는 곳이 이 필드**입니다.

### 10-2. 한 웨이브 안에 출현 그룹 넣기

첫 웨이브에 **출현 그룹 추가**를 누른 뒤 다음 값을 설정합니다.

| 필드 | 예 | 의미 |
|---|---|---|
| 웨이브 이름 | Wave 1 | 편집·테스트에서 구분할 이름 |
| 준비 시간 | 20 | 게임이 사용할 준비 시간 데이터 |
| 스폰 | 서문 스폰 | 어느 입구에서 생성할지 |
| 목표 코어 | 코어 성소 | 어느 코어를 목표로 할지 |
| 경로 가이드 (선택) | 서문 → 광장 → 코어 | 선택적 경유 정보 |
| 게임 키 / 표시 정의 (선택) | Raider_Element | 게임에서 생성할 종류를 연결할 데이터 |
| 출현 수 | 8 | 이 그룹에서 생성할 수 |
| 시작 지연 (초) | 3 | 출현 단계 시작으로부터 첫 생성까지 지연 |
| 출현 간격 (초) | 1 | 다음 개체가 생성되기까지 간격 |

**출현 수는 1 이상, 시작 지연은 0 이상, 간격은 0.05초 이상**으로 설정합니다.

예를 들어 지연 3초·간격 1초·출현 수 4이면 예정 시점은 **3초, 4초, 5초, 6초**입니다. 같은 웨이브의 그룹들은 각자 시작 지연을 기준으로 진행합니다. 목록 아래의 그룹이라고 앞 그룹이 끝난 뒤에 시작하는 것은 아닙니다.

### 10-3. 두 입구에서 동시에 출현시키기

한 웨이브에 출현 그룹을 두 개 넣습니다.

| 그룹 | 스폰 | 목표 | 출현 수 | 시작 지연 | 간격 |
|---|---|---|---:|---:|---:|
| A | 서문 | 코어 성소 | 12 | 0초 | 1초 |
| B | 동문 | 코어 성소 | 9 | 3초 | 1.2초 |

이렇게 설정하면 서문 출현을 먼저 시작하고, 3초 후 동문 출현도 시작합니다. 같은 입구에서 다른 종류의 적을 섞으려면 같은 스폰을 가진 그룹을 하나 더 추가하고 요소 정의를 다르게 지정합니다.

### 10-4. 5웨이브 구성 예시

아래는 설명서 실습용 제안입니다. 게임 밸런스 확정값이나 예제 생성 버튼의 실제 수치를 그대로 옮긴 표는 아닙니다.

| 웨이브 | 출현 구성 | 제작자가 확인할 점 |
|---|---|---|
| 1 | 서문 일반 적 6 | 첫 방어 지점과 코어까지의 거리 |
| 2 | 서문 일반 적 10 | 적이 늘었을 때 통로 여유 |
| 3 | 서문 일반 적 12 + 동문 일반 적 9 | 두 전선 사이의 이동 시간 |
| 4 | 서문 일반 적 12 + 서문 강한 적 2 + 동문 일반 적 10 | 종류별 출현 데이터 구성 |
| 5 | 양쪽 각각 일반 적 14 + 강한 적 2 | 양쪽 입구의 최종 배치 점검 |

**웨이브 추가**를 눌러 5개까지 만들고 각 웨이브에 그룹을 추가합니다. 강한 적은 `Brute_Element` 같은 별도 요소 정의를 만들고 Game Key를 구분할 수 있습니다. 현재 진단에서 강한 적의 체력·공격력이 구현되지는 않으며, 임시 모형의 이동으로 공간을 확인합니다.

### 10-5. 현재 테스트에서 재생되는 범위

현재 진단 모듈은 **선택한 웨이브 한 개**를 재생합니다. 해당 그룹의 시작 지연·간격·출현 수·목표·선택적 경로를 사용합니다.

**준비 시간은 저장되지만 진단에서는 기다리지 않습니다.** 1~5웨이브 자동 진행, 처치 확인, 완료 보상, 승패도 게임 쪽에서 연결해야 합니다. 진단 모형은 코어에 도달하면 도달 수에 집계되고 제거됩니다.

진단 모형은 그룹당 최대 500개로 제한되어 있습니다. 이 제한은 실제 게임의 출현 규칙이 아닙니다.

### 데이터 공유 주의

WaveSet은 장면 밖의 자산입니다. 두 레벨이 같은 WaveSet을 참조하면 내용을 수정했을 때 양쪽에 반영됩니다. 다른 레벨용 웨이브를 만들려면 Project에서 WaveSet을 복제하고 **웨이브 데이터** 필드에 복제본을 연결하세요. 복제한 데이터의 스폰·코어·경로 참조도 새 레벨에 맞춰 다시 지정합니다.

## 11. 검사·테스트·저장

### 11-1. 이동 영역 굽기

1. 지형과 환경 배치가 끝나면 **검사 / 저장** 탭을 엽니다.
2. **이동 영역 굽기 + 전체 검사**를 누릅니다.
3. 오류·경고 목록을 읽고 **보기**로 해당 오브젝트를 선택합니다.
4. 수정 후 다시 굽습니다.

굽기는 실제 Collider를 바탕으로 걸을 수 있는 공간을 계산합니다. 지형 모양이나 벽 위치를 바꾸면 다시 실행하세요. **맵 검사**만 누르면 검사만 진행하고 이동 영역을 새로 만들지는 않습니다.

초기 시설 마커의 박스는 실제 Collider가 아니므로 기본 지형 굽기에 포함되지 않습니다. 바리케이드에 길이 막혔을 때 공격하고 부수는 검사는 실제 시설과 EnemyAI를 연결한 후 진행해야 합니다.

### 11-2. Play 테스트

1. 선택 진단 모듈 `DesertTowerLevelDiagnostics`와 Input System이 준비된 상태인지 확인합니다. 이 프로젝트에는 설치되어 있습니다.
2. **테스트 웨이브**에서 실행할 웨이브를 고릅니다.
3. **저장 후 Play 테스트**를 누릅니다. 장면 저장이 완료되면 Play 모드로 들어갑니다.
4. Game 화면을 클릭해 조작합니다.

| 조작 | 기능 |
|---|---|
| W / A / S / D | 이동 |
| 우클릭을 누른 채 마우스 이동 | 시점 회전 |
| 왼쪽 Shift | 달리기 |
| R | 플레이어 시작점으로 복귀 |
| Unity 상단 Play 버튼 해제 | 편집 상태로 돌아가기 |

결과 표시에서 **Spawned**는 생성 수, **Active**는 이동 중인 수, **Arrived**는 도달 수, **Failed**는 생성·이동 실패 수입니다.

확인할 것은 통로 폭, 급경사·단차, 카메라 가림, 두 전선 이동 거리, 코어까지의 연결입니다. 진단용 플레이어·카메라·모형은 임시 오브젝트입니다. **Play 중 바꾼 값을 영구 편집값으로 기대하지 말고, 종료 후 편집 모드에서 수정하세요.**

### 11-3. 무엇을 저장하는가

| 저장 대상 | 담기는 내용 | 저장 방법 |
|---|---|---|
| 장면 `.unity` | 지형·프리팹의 배치, 마커·영역·경로, 데이터 참조 | **장면 저장** 또는 Unity 장면 저장 |
| WaveSet `.asset` | 웨이브와 출현 그룹 | 웨이브 탭에서 편집, **장면 저장** 버튼으로 자산도 함께 저장 |
| Level Element `.asset` | 종류 키와 표시 정보 | Inspector에서 편집 후 자산 저장 |
| LevelLayout `.asset` | 마커·영역·경로·웨이브 참조 | **배치 데이터 저장** |
| TerrainData·TerrainLayer·재질·길 메시·NavMeshData | 장면이 참조하는 별도 자산 | 생성·편집 후 장면과 함께 보관 |

작업 마무리에는 전용 창의 **장면 저장**을 사용하면 장면과 변경된 자산 저장을 함께 호출합니다. `.unity` 파일 하나만 외부로 복사하면 참조 자산이 누락될 수 있습니다.

**배치 데이터에는 지형·환경 프리팹·재질이 포함되지 않습니다.** 같은 공간에 다른 마커 구성을 적용하거나 배치를 보관하는 용도입니다. WaveSet도 복사본이 아니라 참조로 들어갑니다.

### 11-4. 배치 데이터 가져오기

1. **가져올 배치 데이터** 필드에 LevelLayout 자산을 넣습니다.
2. **현재 마커 구성을 데이터로 교체 (Undo 가능)**를 누릅니다.
3. 기존 마커·구역·경로가 교체되고 지형은 유지됩니다. 레벨 이름·격자 간격·웨이브 참조도 데이터의 값으로 바뀝니다.
4. 원하지 않은 결과면 Ctrl+Z로 되돌립니다.
5. 마커가 지면에 맞는지 검사하고 저장합니다.

기존 구성에 추가하는 동작이 아니라 **교체**입니다. 보관하려면 적용 전에 현재 배치 데이터를 먼저 저장하세요.

### 11-5. 다른 맵으로 복제할 때

장면을 다른 이름으로 저장해도 TerrainData나 WaveSet 같은 참조 자산까지 자동으로 복제되지는 않습니다. 새 맵에서 산세와 웨이브를 독립적으로 바꾸려면 해당 자산도 복제해 연결하거나, **협곡 예제 / 요새 예제**로 새로 생성한 장면에서 시작하세요. 예제 생성은 새 TerrainData·웨이브 데이터를 만듭니다.

## 12. 따라 하기: 두 진입로를 가진 협곡 맵

아래 순서대로 진행하면 기능을 한 번씩 사용해 볼 수 있습니다. 예제를 변형하는 실습이므로 빈 Terrain부터 만드는 경우보다 작업이 적습니다.

### 단계 A — 맵 공간 준비

1. **협곡 예제**를 눌러 새 예제를 생성합니다.
2. 원하는 장면 이름으로 저장합니다.
3. **Terrain 편집하기**로 중앙 분지와 두 입구를 확인합니다.
4. 큰 브러시로 산세를 조금 조정하고, 방어 지점은 Set Height로 평탄하게 유지합니다.
5. 준비한 바위 프리팹을 **배치할 프리팹**에 넣어 길 양옆에 몇 개 배치합니다.
6. 바위 때문에 길 전체가 막히거나 고지 경사로가 끊기지 않았는지 확인합니다.

**완료 기준:** 두 입구, 중앙 분지, 코어 구역, 후방 연결로를 Scene에서 구별할 수 있습니다.

### 단계 B — 마커와 설치 구역

1. **마커** 목록에서 기존 코어·서문·동문 스폰을 찾아 Label을 알아보기 쉽게 바꿉니다.
2. 이동한 지면에 맞춰 위치를 조정하고 **지면에 맞추기**를 사용합니다.
3. 시작점과 부활점 주변에 공간을 남깁니다.
4. `Cobra_Element`를 만들고 기존 초기 시설 마커에 지정합니다.
5. **구역 / 경로**에서 기존 서측·동측 설치 구역의 꼭짓점을 새 지형에 맞게 조정합니다.
6. 코어와 스폰 출구의 설치 금지 구역을 유지합니다.

**완료 기준:** 코어 1개, 시작점 1개, 스폰 2개가 있으며 시설 표시가 지형 속에 묻히지 않습니다.

### 단계 C — 경로와 웨이브

1. 기존 서측·동측 경로를 선택하고 새 바위 배치에 맞게 경유점을 이동합니다.
2. 웨이브 데이터가 이 레벨의 자산인지 확인합니다.
3. Wave 1은 서문 그룹 하나, 출현 수 6·지연 0·간격 1초로 설정합니다.
4. Wave 3에는 동문 그룹을 추가하거나 기존 그룹을 편집합니다. 지연 3초로 설정해 두 입구의 출현 시차를 확인합니다.
5. 각 그룹의 스폰·목표·경로 가이드가 일치하는지 확인합니다.

**완료 기준:** 각 웨이브가 어느 입구를 사용하는지 그룹 목록만 보고 알 수 있습니다.

### 단계 D — 검증과 보관

1. **이동 영역 굽기 + 전체 검사**를 실행합니다.
2. 서측·동측 **실제 경로 표시**를 각각 확인합니다.
3. Wave 1을 Play 테스트하고, 종료 후 Wave 3도 테스트합니다.
4. 플레이어로 양쪽 방어 지점을 오가며 통로 폭과 카메라를 확인합니다.
5. 편집 모드로 돌아와 **장면 저장**, 필요하면 **배치 데이터 저장**을 실행합니다.

**완료 기준:** 선택 웨이브의 모형이 코어까지 도달하고, 다음 수정에 사용할 장면과 참조 자산이 저장되어 있습니다.

## 13. 자주 생기는 문제

| 증상 | 확인·해결 방법 |
|---|---|
| Scene을 클릭해도 배치되지 않음 | 도구 활성화, 편집 레벨 선택, 지면 Collider, 지면이 루트의 자식인지 확인 |
| 빈 공간에 블록을 놓을 수 없음 | 먼저 Terrain이나 Collider가 있는 바닥을 생성. 허공 클릭 배치는 지원하지 않음 |
| 마커가 보이지 않음 | Scene Gizmos와 **검사 / 저장**의 표시 옵션 확인. Hierarchy나 목록에서 선택 |
| Terrain 브러시 대신 마커가 계속 놓임 | Esc 또는 **선택 모드**로 전용 배치 도구를 끝낸 뒤 Terrain 선택 |
| 프리팹이 지면에 묻힘 | 프리팹 원점 확인. 부모 원점을 바닥 기준으로 정리하거나 배치 후 Y 수정 |
| 바위를 놓았는데 적이 통과함 | Collider와 레벨 루트 소속 확인, 이동 영역 다시 굽기 |
| Terrain에 재질을 넣었는데 기대한 페인트가 안 됨 | 일반 Material 필드가 아니라 Paint Texture의 TerrainLayer 사용 |
| 길이 지형에 묻히거나 번쩍거림 | 지형 높이 확인, 지면 위 간격 조절 후 길 재생성. 자동 지형 절삭은 없음 |
| 마커 Footprint를 바꿔도 크기가 같음 | Definition의 Footprint가 우선 적용되는지 확인 |
| 타워 프리팹을 정의에 넣었는데 박스로 보임 | 현재 Preview Prefab은 참조 저장용. 마커·진단은 임시 표시 사용 |
| 영역 완성 버튼이 비활성화됨 | 영역 모드인지, 최소 3점을 찍었는지 확인 |
| 영역 생성이 거부됨 | 변의 교차 또는 점 간 높이 차 확인. 평탄한 구간별로 나눠 생성 |
| ID 중복 오류 | 복제 마커의 ID를 새로 만들고 연결 확인. 영역·경로 복제는 Inspector의 Id도 고유하게 관리 |
| 웨이브 스폰·목표 불일치 | 선택 가이드의 양 끝과 그룹의 스폰·목표가 같은지 확인 |
| 이동 영역 밖 / 길이 끊김 | 다시 굽기, 마커·경유점을 바닥에 맞추기, 경사로 연결과 통로 폭 확인 |
| Play 테스트 버튼이 비활성화됨 | 진단 모듈과 Input System 설치 여부, Console 컴파일 오류 확인 |
| Play에서 움직이지 않음 | Game 화면 포커스, Input System 입력 설정 확인. 단독 키 입력 없이 Shift만 누르면 이동하지 않음 |
| Wave 2로 자동 진행하지 않음 | 현재 진단은 선택 웨이브 한 개만 실행. 종료 후 다른 웨이브 선택 |
| 적이 타워를 공격하지 않음 | 현재 진단은 이동 검사. 실제 EnemyAI·시설 전투는 별도 연결 |
| 다른 레벨도 함께 바뀜 | TerrainData·WaveSet·요소 정의·재질을 공유하고 있는지 확인 |

검사 통과는 모든 게임 상황의 정상 동작을 보장하는 뜻은 아닙니다. 현재 겹침 검사는 일부 근사·표본 판정이며, 카메라 가림이나 실제 시설 배치 조합은 플레이로 확인해야 합니다.

## 14. 다른 프로젝트로 가져가기

### 에디터 도구만 전달

**Tools → Desert Tower → Export Editor Package…**를 사용합니다. 기본 편집기와 설명서가 포함되며, 사용자 레벨과 선택 진단 모듈은 포함되지 않습니다.

### 이동 테스트 모듈도 전달

**Tools → Desert Tower → Export Optional Diagnostics Package…**를 별도로 사용합니다. 받는 프로젝트에 기본 에디터와 Input System이 필요합니다. 기본 에디터의 NavMesh 편집·검사에는 AI Navigation이 필요합니다. `.unitypackage`는 이 패키지 의존성을 자동 설치하지 않습니다.

### 만든 레벨도 전달

장면과 참조 자산을 함께 전달해야 합니다. Project에서 관련 장면·자산을 선택해 Unity의 일반 패키지 내보내기를 사용하고 포함 목록을 확인하세요. TerrainData·TerrainLayer·재질·모델·프리팹·WaveSet·LevelLayout·NavMeshData가 필요한지 살펴봅니다. **전용 에디터 내보내기 버튼은 사용자 레벨을 내보내는 버튼이 아닙니다.**

프로젝트 내부의 기본 생성 위치는 다음과 같습니다.

| 위치 | 내용 |
|---|---|
| `Assets/DesertTowerLevelEditor` | 기본 에디터와 설명서 |
| `Assets/DesertTowerLevelDiagnostics` | 선택적 이동 진단 모듈 |
| `Assets/DesertTowerLevels/Scenes` | 예제 장면 |
| `Assets/DesertTowerLevels/Data` | 웨이브·배치 데이터 |
| `Assets/DesertTowerLevels/Terrain` | TerrainData·표면 레이어 |
| `Assets/DesertTowerLevels/Meshes` | 생성한 길 메시 |
| `Assets/DesertTowerLevels/Materials` | 기본·예제 재질 |
| `Assets/DesertTowerLevels/Navigation` | 구운 이동 영역 |

게임 코드 연결 방식과 책임 구분은 [ARCHITECTURE.md](ARCHITECTURE.md), 기능 요약은 [README.md](README.md)를 참고하세요.
