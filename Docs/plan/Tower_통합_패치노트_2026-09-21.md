# 타워 통합 패치 노트 (2026-09-21)

카탈로그(`Assets/Facility/Generated/FacilityCatalog.asset`)가 가리키는 타워 프리팹이
`Assets/Facility/Generated/Towers/*`(시설 팀 사본)에서 **`Assets/2.Model/Prefabs/Tower_*.prefab`(타워 팀 원본)** 으로 바뀐 뒤,
그 프리팹에 없던 통합용 부품 때문에 생긴 인게임 증상 3가지를 고쳤습니다.

**담당자 코드의 기존 줄은 지우지 않았고**, 바꾼 자리마다 `[통합 추가]` / `[통합 수정]` 표시와 이유를 적어 두었습니다.

## 고친 증상

| 증상 | 원인 | 고친 곳 |
|---|---|---|
| 타워가 부서진 자리에 **다시 지을 수 없다** | 건설 서비스가 `FacilityHealth`(시설 팀 구체 타입)에서만 파괴 알림을 받아, `TowerHealth`가 붙은 타워는 구독이 안 돼 슬롯이 영원히 점유 상태로 남음 | 시설 팀 코드 3개 |
| 체력이 깎여도 **수리 UI가 뜨지 않는다** | 같은 이유로 체력을 못 읽고, `TowerHealth`에 `IRepairable`이 없어 수리 대상에서 제외됨 | 시설 팀 코드 + `TowerHealth` |
| 우두머리가 폭탄을 던져도 **타워가 멈추지 않는다** | `TowerDisableReceiver`가 4개 프리팹 어디에도 없었고, 있어도 끄는 대상 목록이 구형 컴포넌트뿐이라 끌 것이 0개 | 수신기 + 프리팹 4개 |

## 1. 담당자 코드 수정 (더하기만, 기존 줄 보존)

### `Assets/3.Script/Tower/TowerHealth.cs`
| 바뀐 점 | 이유 |
|---|---|
| 인터페이스 목록에 `IRepairable` 추가 | 건설 시스템의 수리 메뉴(`FacilityBuildService.TryRepair`)는 시설의 `IRepairable`에 회복을 맡깁니다. 이게 없으면 타워는 수리 대상으로 잡히지 않아 **수리 UI 자체가 뜨지 않습니다** |
| `public float Repair(float amount)` 추가 | 살아 있을 때만 `HP`를 `MaxHP`까지 올리고 실제 회복량을 돌려줍니다. `TakeDamage`와 같은 방식으로 `HealthChanged`를 알려 체력바·HUD가 그대로 따라옵니다. **비용(마나)과 수리 가능 여부는 부르는 쪽이 먼저 확인**하므로 여기서는 체력만 다룹니다 |

기존 필드·메서드는 하나도 건드리지 않았습니다.

### `Assets/3.Script/Tower/TowerHitBox.cs`
| 바뀐 점 | 이유 |
|---|---|
| 인터페이스 목록에 `IFacilityKind` 추가 | 적은 콜라이더에서 `GetComponentInParent<ICombatTarget>()`으로 대상을 찾습니다. **Hit Box 콜라이더가 먼저 잡히면 `TowerHitBox`가 돌아오는데**, 여기에 종류 ID가 없으면 우두머리의 철거 폭탄처럼 "`tower.cobra`만 노린다"는 조건이 본체를 못 알아보고 지나칩니다(어느 콜라이더가 먼저 잡히느냐에 따라 되기도 하고 안 되기도 하던 상태) |
| `public string DefinitionId` 추가 | 종류 ID는 본체(`towerHealth`)가 정한 값을 그대로 전달합니다. 본체가 없으면 빈 문자열(= 종류를 밝히지 않음) |

### `Assets/3.Script/Tower (Legacy)/ObjectPooling.cs`
| 바뀐 점 | 이유 |
|---|---|
| `GetObject()` 맨 앞에 `if (Objects == null) Awake();` | **관(Coffin) 타워를 건설로 지으면 NullReferenceException이 나면서 아예 안 지어지던 문제.** `Instantiate`는 오브젝트를 하나씩 `Awake → OnEnable` 순으로 부르기 때문에, 부모 `Tower (Coffin)`의 `SummonManager.OnEnable`이 자식 `Creature Pool`의 `Awake`보다 **먼저** 실행됩니다. 씬에 미리 놓아 둘 때는 모든 `Awake`가 먼저 돌아 드러나지 않던 문제입니다 |
| `Awake()` 맨 앞에 `if (Objects != null) return;` | 위에서 먼저 만들었을 때 풀을 두 번 만들지 않게 |

> 근본 해결은 `SummonManager`가 소환 시점을 `Start` 이후로 미루거나 풀을 명시적으로 초기화하는 쪽입니다.
> 담당자 설계를 바꾸지 않으려고 **호출 시점에 늦게 만드는(lazy) 방식**으로만 막아 두었습니다.

## 2. 우리 쪽(통합) 코드 수정

### `Assets/3.Script/Tower (Legacy)/TowerDisableReceiver.cs`
끌 컴포넌트 자동 탐색 목록에 **현행 타워의 공격 체인**을 추가했습니다. 기존 구형 4종(`FindEnemy`, `RotateTower`, `FirePointAim`, `RangeController`)은 그대로 두어 예전 프리팹도 계속 동작합니다.

```
TargetDetector, TargetSelector, TowerEmit, TowerAreaEffect,
ManaRecovery, SummonManager, RotateToTarget, AimToTarget, FireActivate
```

`TowerAreaEffect`는 추상 클래스라 코브라의 `FireDamageArea`와 오벨리스크의 `SlowArea`가 함께 잡힙니다.
끌 대상을 하나도 못 찾으면 경고를 남깁니다(조용히 안 멈추는 일이 없도록).

### `Assets/Facility/Runtime/` (시설 팀 코드)
체력 컴포넌트를 **구체 타입이 아니라 인터페이스로** 잡도록 바꿨습니다. `SandGuard.Facility.Runtime`은 asmdef라 `Assembly-CSharp`의 `Tower.TowerHealth`를 이름으로 부를 수 없어, 공용 어휘가 `DesertTower.Gameplay.Abstractions`의 인터페이스뿐입니다.

| 파일 | 바뀐 점 |
|---|---|
| `FacilityInstance.cs` | `FacilityHealth Health` → `IHealth Health` / `ILifeState Life` / `IRepairable Repairable`. 타워 팀 프리팹은 체력이 루트가 아니라 자식에 있어 `GetComponentInChildren`으로 찾습니다. 시설 ID를 맞출 수 없는 남의 체력 컴포넌트라면 **반대로 그쪽 전투 ID를 따라가** 한 값으로 유지합니다 |
| `FacilityBuildService.cs` | 파괴 알림을 `Life.Despawned`로 구독. 파괴 시 시설 뿌리를 꺼서 시체 모양을 통일(타워 팀 체력은 자기 오브젝트만 꺼서 사거리 원·판정 상자가 남았음). 수리는 `Repairable.Repair`. 체력 컴포넌트를 못 찾으면 **에러 로그** |
| `FacilityBuildMenu.cs` | 수리 메뉴 조건을 인터페이스 기준으로. 수리를 지원하지 않는 시설은 수리 타일이 뜨지 않습니다 |

## 4. 담당자께 확인 부탁드리는 것

1. **`Tower_Obelisk.prefab`의 `TowerStatus.MaxHP`가 `100000`입니다.** 디버그 값으로 보입니다. 이 값이 최대 체력의 주인이라(카탈로그의 `maxHealth: 150`은 타워에 대해 무시됩니다) 오벨리스크는 사실상 안 부서지고, 수리비도 이 값 기준으로 계산됩니다. 코브라는 `200`입니다.
2. **`Tower Base.prefab`에서 `Range Circle` 자식이 없어졌습니다.** 받침의 `FacilityAnchor.onlyWhenOccupied`(시설이 있을 때만 켜는 오브젝트)가 그 자식을 가리키고 있었습니다. 지금은 다른 오브젝트를 가리키고 있으니, 의도한 것이 맞는지 봐 주세요.
3. **`Tower_Cobra.prefab`에 깨진 스크립트 참조가 하나 있습니다**(`guid: 474bcb49853aa07438625e644c072ee6`, 프로젝트에 해당 `.cs`가 없음).
4. `SummonManager`의 소환 시점(위 1절 `ObjectPooling` 항목)은 임시로 막아 둔 것이라 근본 해결을 부탁드립니다.

## 5. 회귀 테스트

`FacilityPlayModeTests.EveryCatalogTowerIsRepairableRebuildableAndStoppable` 를 새로 넣었습니다.
**카탈로그에 든 타워 전부**를 실제로 짓고, 체력·수리·정지 배선이 있는지, 부수면 자리가 비고 다시 지어지는지 확인합니다.

기존 테스트들이 특정 프리팹 **경로를 직접 열고 있어서**, 카탈로그만 다른 프리팹으로 바뀌면
테스트는 초록인데 인게임만 깨지는 상태가 됐던 것이 이번 일의 근본 원인입니다.
`ChiefBombTowerIntegrationTests`도 사본 대신 카탈로그가 실제로 짓는 프리팹을 보도록 바꿨습니다.
