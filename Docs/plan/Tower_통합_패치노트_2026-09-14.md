# 타워 통합 패치 노트 (2026-09-14)

타워 담당자 브랜치(`Tower`, `2cfc6ae Tower Fix`)를 `feature/generated`에 머지한 뒤, 게임의 실제 적·코어와 연결하면서 바꾼 내용입니다.
**담당자 코드의 기존 줄은 지우지 않고 주석으로 남겼고**, 바꾼 자리마다 `[통합 수정]` / `[통합 추가]` 표시와 이유를 적어 두었습니다.

## 역할 나누기 (합의한 기준)

| 담당 | 내용 |
|---|---|
| **타워(담당자 코드 기준)** | 누구를 조준하고, 어떤 범위에, 무엇을 할지(피해·둔화) |
| **적(generated 기준)** | 이동, 체력, 방어(방패), 피격 연출, 사망, 둔화가 걸린 뒤의 속도 |
| **연결 방식** | 타워는 적에게 **요청만** 보낸다: 피해는 `IDamageable.TakeDamage`, 둔화는 `ISlowable.Slow` |

타워가 적의 상태를 직접 적어 넣던 임시 적 `EnemyState` 방식은 타워 코드에서 쓰지 않습니다. `EnemyState.cs`, `EnemyMove.cs` 파일은 **그대로 두었습니다**. Tower.unity의 `Enemy Capsule`이 쓰고 있습니다.

|---|---|

## 2. 새로 추가한 코드

### `Assets/3.Script/Tower/TowerDisableReceiver.cs` (신규)
- **왜**: 기획서의 보스 "철거 폭탄"은 주변 시설을 5초 정지시킵니다. 폭탄(적 코드)은 타워 내부를 건드리지 않고 `CombatEffectSignals.TowerDisableRequested`로 "이 타워를 N초 정지해 달라"는 요청만 보내므로, 받아서 실제로 멈추는 쪽이 타워에 필요합니다.
- **하는 일**
  - 요청 대상 ID가 본체의 전투 ID와 같으면, 그 시간 동안 `FindEnemy`, `RotateTower`, `FirePointAim`, `RangeController`를 끄고 본체 파티클(화염)을 멈춥니다.
  - 끝나면 원래대로 켭니다. 정지 중 요청이 또 오면 더 긴 쪽으로 늘립니다.
- **연출(선택)**: `Disabled_Vfx`에 프리팹을 넣으면 정지 동안 본체에 띄우고 본체 색을 어둡게 합니다. 현재 코브라에만 `VFX_Facility_Disabled_Loop`를 연결했습니다.

## 4. 확인이 필요한 사항 (담당자)

1. **오벨리스크 `Slow Range` 반경이 0.5m입니다.** 트리거 방식일 때도 같은 크기였습니다. 둔화 범위를 탐지 사거리(20m)나 표시 원 크기에 맞추려는 의도였다면 콜라이더 반경을 조정해 주세요. 통합 테스트는 이 확인을 위해 테스트 안에서만 6m로 넓혔습니다.
2. **`Tower.unity`의 `Enemy Capsule`(임시 적)은 이제 타워에 반응하지 않습니다.** 타워가 `ICombatTarget`/`IDamageable`/`ISlowable`만 보기 때문입니다. 타워를 확인하려면 실제 적 프리팹(`Assets/Enemy/Generated/Enemy.prefab`)을 NavMesh가 있는 바닥에 두는 방식을 권합니다.
3. **타워가 아직 프리팹이 아닙니다.** 본체는 `Tower.unity` 안에만 있어서 Level에서는 받침만 보입니다. 프리팹으로 만들면 위 3번의 컴포넌트가 그대로 따라가도록 메뉴를 다시 실행하면 됩니다(프리팹 경로를 알려주시면 메뉴에 추가하겠습니다).
4. **새 인스펙터 수치**(피해량·간격)는 임시값입니다.

## 6. 타워 설치·수리 (추가, 2026-09-14)

담당자 파일(`Tower.unity`, `Tower Base.prefab`, `3.Script`)은 **이번 단계에서 바꾸지 않았습니다.** 복제본·변형만 우리 폴더(`Assets/Facility/Generated/Towers/`)에 만들었습니다.

| 만든 것 | 내용 | 이유 |
|---|---|---|
| `Tower_Cobra.prefab`, `Tower_Obelisk.prefab` | `Tower.unity`의 본체를 그대로 복제한 **임시 프리팹**. 건설 등장 연출(`VfxPopIn`)만 추가 | 담당자 타워 본체가 아직 프리팹이 아니라서. 공식 프리팹이 생기면 카탈로그의 프리팹 경로만 바꾸면 됩니다 |
| `TowerBaseAnchor.prefab` | `Tower Base.prefab`의 **프리팹 변형** + `FacilityAnchor`(건설 받침) | 원본 받침을 수정하지 않고 건설용 설정만 얹기 위해. 원본이 바뀌면 변형도 따라갑니다 |
| 받침의 `Range Circle` | 본체가 있을 때만 켬 | `ShowRange`가 켜질 때 본체의 `DetectRange`를 찾는데, 본체 없이 켜면 매 프레임 null 오류가 납니다 |
| 카탈로그 | 화염 코브라 **40**, 모래시계 오벨리스크 **55** | 코브라는 기획서 값, 오벨리스크는 기획서에 없어 해골 소환진 값을 임시로 사용 |

- **설치**: 기존 시설 건설과 같은 흐름입니다(빈 받침 접근 → 메뉴 → 번호 키 → 등장 연출). 마나는 예약해 두었다가 설치가 끝나면 차감하고, 실패하면 차감하지 않습니다.
- **수리**: 체력이 깎인 타워에 다가가면 수리 메뉴가 뜨고, **1번 키로 즉시 전체 수리**합니다. 비용 = 건설비 × 잃은 체력 비율 × 0.5(올림). 살아 있는 타워만 가능합니다.
- **파괴 후**: 받침이 비고, 다시 설치할 수 있습니다. 이때 꺼져 있던 옛 본체는 정리됩니다.
- **강화·철거**는 아직 없습니다(`Locked` 반환).
- **확인한 문제**: 본체의 `Damage Range` 메시는 담당자 씬에서 꺼져 있는데, 건설 등장 연출이 끝날 때 다시 켜지는 문제가 있었습니다. `VfxPopIn`이 원래 켜져 있던 렌더러만 다루도록 고쳤습니다(담당자 코드 아님).

## 7. Level.unity 타워 슬롯 연결 (추가, 2026-09-14)

레벨 담당자가 `7ff33bd tower base`로 놓은 **임시 받침 메시**(`Assets/2.Model/Prefabs/Level/Temp/Mesh.prefab`) 8개 자리를 실제 설치 자리로 연결했습니다.
메뉴: **`SandGuard > Facility > Set Up Level Tower Slots (Level.unity)`** (여러 번 실행해도 중복 생성하지 않음)

| 변경 | 내용 | 이유 |
|---|---|---|
| 건설 슬롯 8개 추가 | `Desert Tower Level3` 아래 `건설 슬롯` 오브젝트(레벨 에디터가 만드는 것과 같은 형식). 임시 메시와 같은 위치·방향, 크기 4×4, 허용 `cobra`·`obelisk`, 바닥 ID는 높이별 `tower-floor-14/26/38` | 설치 서비스가 슬롯 단위로 자리와 허용 시설을 확인함 |
| 임시 받침 메시 8개 **비활성화**(삭제 안 함) | 씬 최상위의 `Mesh` ~ `Mesh (7)` | 설치 받침(`TowerBaseAnchor`)에 같은 받침 외형이 들어 있어 겹침 |
| 슬롯마다 `TowerBaseAnchor`, 씬에 건설 서비스·메뉴 | 플레이어 마나 지갑과 연결 | 설치·수리 흐름 |
| **경로 노드 8개 도착 반경 0.5 → 3m** (`GraphIntegration.prefab`: T5, T6, T7, T8, NE/NW/SE/SW L3) | 받침 반폭 2 + 적 반경 0.5 + 여유 0.5 | 받침이 노드 바로 위(0.3~1.8m)에 있어서, 받침의 NavMesh 장애물이 노드를 덮으면 적이 도착하지 못하고 웨이브가 멈춤. 코어와 같은 방식으로 받침 가장자리에 닿으면 도착으로 처리 |

**확인(배치 모드로 Level 플레이)**
- 슬롯 8 / 받침 8 / 서비스·메뉴 있음. 설정 검사 오류 0개.
