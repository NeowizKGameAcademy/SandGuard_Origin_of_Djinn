# DESERT TOWER 공통 전투 기반 시스템 설계

버전: 0.2
작성일: 2026-09-06
기준 문서: Desert_Tower_상세_게임기획서_v0.2 (11.1 "공통 체력·피해·사망 처리와 진영 구분")
문서 성격: 구현 전 설계 기준. 코드 없음. 기획서 규칙과 충돌하면 기획서를 우선한다.

---

## 1. 정의

공통 전투 기반은 **전투 개체 하나의 체력과 생존 상태를 관리하고, 피해를 접수해 적용하며, 그 결과를 신호로 내보내는** 시스템이다.

이 시스템은 신호를 누가 받는지 알지 못하며, 알아서는 안 된다. 신호를 받는 시스템이 없어도, 백 개가 있어도 이 시스템의 동작은 같다.

### 1.1 소유하는 것

- 전투 개체의 체력: 저장, 감소, 회복, 상한
- 전투 개체의 생존 상태와 그 전이
- 피해 요청의 접수, 검증, 적용
- 체력 0 도달 시 개체를 최종 상태로 만들고 신호를 정확히 한 번 내는 것
- 거리·시야 판정의 기준점: 피격 지점, 공격 발생 지점

### 1.2 알지 않는 것

- 개체가 누구에 의해, 언제, 어디에 생성되는가
- 전장에 어떤 개체들이 있는가
- 진영 간 적대 관계의 정의 (FactionProfile 자산을 읽기만 한다)
- 개체 사이의 소속·소유 관계
- 누구를 공격 대상으로 고르는가
- 사거리·시야·접근 가능성 판정
- 마나·경험치 보상
- 이동 경로, 점유, 설치 구역
- 웨이브, 승패, 재시작 절차
- 연출, 음향, HUD

## 2. 전투 개체

### 2.1 속성

| 속성 | 설명 |
|---|---|
| 정의 참조 | 2.3의 편집 가능한 데이터 자산 |
| 진영 | FactionProfile이 정의한 진영 중 하나 |
| 최대 체력 | 정의에서 읽음 |
| 현재 체력 | 0 이상 최대 체력 이하 |
| 생존 상태 | 2.2의 상태 중 하나 |
| 대상 가능 여부 | 생존 상태와 보호 시간에서 파생되는 읽기 전용 값 |
| 피격 지점 | 거리·시야 판정에 쓰는 월드 위치. 정의의 오프셋을 개체 위치에 더한 값 |
| 공격 발생 지점 | 이 개체의 공격이 시작되는 월드 위치. 공격하지 않는 개체는 없음 |

### 2.2 생존 상태

```
[생존] ─ 체력 0 ─→ [종료 중] ─ 종료 연출 시간 경과 ─→ [제거됨]         (제거형)
[생존] ─ 체력 0 ─→ [무력화] ─ 회복 요청 ─→ [생존]                      (유지형)
[생존 / 무력화] ─ 소멸 요청 ─→ [제거됨]
```

개체가 제거형인지 유지형인지는 정의 자산의 값이다.

| 상태 | 대상 가능 | 피해 접수 | 충돌·공격 기능 | 비고 |
|---|---|---|---|---|
| 생존 | 예 (보호 중이면 아니오) | 예 | 켜짐 | |
| 종료 중 | 아니오 | 아니오 | 꺼짐 | 모형만 남는 연출 구간 |
| 무력화 | 아니오 | 아니오 | 꺼짐 | 체력 0, 개체는 남음 |
| 제거됨 | 아니오 | 아니오 | 없음 | |

상태 전이 규칙:

- 생존 → 종료 중 / 무력화 전이는 체력이 0이 되는 그 피해 적용에서 단 한 번 일어난다. 같은 프레임에 여러 피해가 도달해도 전이와 신호는 한 번이다.
- 전이가 일어나는 순간, 신호를 보내기 **전에** 개체의 충돌·공격 기능을 끄고 대상 가능 여부를 거짓으로 만든다. 신호를 받은 쪽이 개체를 조회하면 항상 최종 상태를 본다.
- 소멸은 체력 0 도달 신호를 내지 않는다. 소멸 신호만 낸다.
- 이미 제거됨 상태인 개체에 대한 모든 요청은 무시한다.

### 2.3 편집 가능한 데이터

| 항목 | 설명 |
|---|---|
| 진영 | FactionProfile의 진영 식별자 |
| 최대 체력 | |
| 체력 0 처리 | 제거형 / 유지형 |
| 종료 연출 시간 | 제거형만. 종료 중 → 제거됨까지의 시간 |
| 부활 보호 시간 | 유지형만. 회복 직후 대상 불가·피해 거부 시간. 초기값 0 |
| 피격 지점 오프셋 | 개체 위치 기준 |
| 공격 발생 지점 오프셋 | 개체 위치 기준. 공격하지 않으면 비움 |

이 자산에 넣지 않는 것: 이동 속도, 공격력, 사거리, 공격 간격, 보상, 비용, 크기.

## 3. 피해

### 3.1 피해 요청

| 항목 | 필수 | 설명 |
|---|---|---|
| 대상 개체 | 예 | |
| 피해량 | 예 | 0 이상 |
| 가해 진영 | 예 | 가해 개체가 없어도 반드시 있음 |
| 가해 개체 | 아니오 | 실제로 공격한 개체 |
| 피해 원인 | 아니오 | 식별자. 기반은 값을 해석하지 않고 신호에 그대로 싣는다 |
| 적중 위치·방향 | 아니오 | 신호에 그대로 싣는다 |

### 3.2 적용 순서

1. 대상이 생존 상태가 아니면 거부.
2. FactionProfile에서 가해 진영 → 대상 진영이 적대가 아니면 거부.
3. 대상이 보호 시간 중이면 거부.
4. 현재 체력에서 피해량을 뺀다. 0 미만은 0.
5. 체력 변경 신호, 피해 받음 신호를 보낸다.
6. 체력이 0이면 2.2의 전이를 수행하고 체력 0 도달 신호를 보낸다.

거부는 오류가 아니다. 요청자에게 거부 사실만 돌려주고 조용히 끝난다.

### 3.3 회복

| 요청 | 대상 상태 | 동작 |
|---|---|---|
| 회복(양) | 생존 | 현재 체력에 더하고 최대 체력으로 상한. 체력 변경 신호 |
| 부족 체력 조회 | 생존 | 최대 − 현재를 돌려준다. 상태 변화 없음 |
| 완전 회복 | 무력화 | 생존으로 전이, 최대 체력, 보호 시간 시작. 체력 변경 신호, 회복 신호 |

회복 요청의 허용 시점(웨이브 사이, 5초 후 등)과 비용은 요청자가 판단한다. 기반은 상태만 확인한다.

### 3.4 소멸

생존 또는 무력화 상태의 개체를 제거됨으로 만든다. 체력 0 도달 신호 없이 소멸 신호만 낸다.

---

## 4. 진영

- 개체는 FactionProfile이 정의한 진영 식별자 하나를 갖는다.
- 기반은 FactionProfile에 "A 진영이 B 진영에 적대인가"만 묻는다.
- 같은 진영, 또는 비적대 진영의 피해 요청은 3.2의 2단계에서 거부된다. 아군 피해 규칙은 FactionProfile의 내용으로 결정되며 기반은 규칙을 갖지 않는다.

---

## 5. 기준점

거리·시야 판정을 수행하는 시스템이 공통으로 읽을 수 있도록 다음 값을 개체마다 제공한다.

- **피격 지점**: 이 개체를 향한 거리와 시야를 잴 때 쓰는 위치. 발 위치가 아니라 정의 자산의 오프셋을 더한 몸통 위치.
- **공격 발생 지점**: 이 개체에서 나가는 거리와 시야를 잴 때 쓰는 위치.

판정 자체(어떤 층을 장애물로 볼지, 사거리를 만족하는지)는 기반이 하지 않는다.

---

## 6. 신호

기반이 내보내는 신호는 다음 다섯 가지다. 기반은 수신자의 존재, 수, 순서를 알지 못한다. 수신자 사이의 처리 순서는 보장하지 않는다.

| 신호 | 시점 | 실리는 데이터 |
|---|---|---|
| 체력 변경 | 체력 값이 바뀔 때마다 | 개체, 이전 체력, 현재 체력, 최대 체력 |
| 피해 받음 | 피해 요청이 거부되지 않고 적용된 직후 | 개체, 피해 요청 전체, 실제 적용된 피해량 |
| 체력 0 도달 | 생존 → 종료 중 또는 무력화 전이 직후 | 개체, 정의 참조, 진영, 마지막 피해 요청 |
| 회복 | 무력화 → 생존 전이 직후 | 개체 |
| 소멸 | 소멸 요청 처리 직후 | 개체 |

신호 시점의 불변 조건:

- 신호를 보내는 시점에 개체의 상태는 이미 최종 상태다. 신호를 받고 개체를 조회하면 체력, 생존 상태, 대상 가능 여부, 충돌·공격 기능 상태가 모두 갱신되어 있다.
- 체력 0 도달 신호는 개체당 평생 한 번이다. 유지형 개체가 회복 후 다시 체력 0이 되면 그때 다시 한 번이다. 즉 "생존 상태에서 나갈 때마다 한 번"이다.
- 소멸된 개체에 대해서는 이후 어떤 신호도 나오지 않는다.

## 7. 어셈블리

```
DesertTower.Combat.Runtime
  └─ Unity 기본 타입만 참조. Levels.Runtime, AI Navigation, Input System을 참조하지 않는다.
```

FactionProfile은 이 어셈블리 안의 자산 타입으로 두되, 내용(진영 목록과 적대 표)은 데이터다.

씬 없이 EditMode에서 검증 가능해야 한다.

## 8. 검증 기준

| 항목 | 기대 결과 |
|---|---|
| 체력 1인 개체에 같은 프레임 피해 3건 | 체력 0 도달 신호 1회, 피해 받음 신호 1회 |
| 비적대 진영의 피해 요청 | 거부, 체력 불변, 신호 없음 |
| 종료 중 개체에 피해 요청 | 거부, 신호 없음 |
| 체력 0 도달 신호 수신 시점에 개체 조회 | 대상 가능 거짓, 충돌·공격 기능 꺼짐 |
| 유지형 개체 체력 0 | 무력화, 제거되지 않음, 체력 0 도달 신호 1회 |
| 유지형 개체 완전 회복 | 생존, 최대 체력, 회복 신호 1회, 보호 시간 동안 피해 거부 |
| 제거형 개체 체력 0 후 종료 연출 시간 경과 | 제거됨 |
| 소멸 요청 | 소멸 신호 1회, 체력 0 도달 신호 0회 |
| 제거된 개체에 모든 요청 | 무시, 신호 없음 |
| 회복 요청이 최대 체력 초과 | 최대 체력으로 상한 |
| 피해 원인·적중 정보가 있는 요청 | 피해 받음 신호에 그대로 실림 |

---

## 9. 남은 결정

- 체력 자료형: 내부 소수, 표시 정수 올림을 초기값으로 한다.
- 보호 시간의 구현: 대상 불가로 할지, 피해 거부만 할지. 초기값은 둘 다.
- 종료 중 상태의 모형이 시야 판정의 장애물인가. 초기값은 아님(충돌 기능이 꺼지므로).
- 피해 원인 식별자의 형식. 열거형이 아닌 자산 참조 또는 문자열로 두어 기반 수정 없이 추가 가능하게 한다.
