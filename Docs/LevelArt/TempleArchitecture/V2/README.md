# Desert Temple — courtyard revision

적용 씬: `Assets/TempleArt/ArchitectureV2/Level_TempleCourtyard.unity`

프리팹: `Assets/TempleArt/ArchitectureV2/DesertTemple_Courtyard.prefab`

Blender 원본: `Docs/LevelArt/TempleArchitecture/V2/Temple_Courtyard_v2.blend`

이전 구현의 넓은 상부 기단이 마당을 채우고, 모든 층에 회랑이 반복되던 문제를 수정했다. 기존 씬과 FBX를 덮어쓰지 않고 새 적용 씬을 만들었다.

## 컨셉을 기준으로 수정한 내용

| 비교 항목 | 이전 구현의 문제 | 이번 수정 |
|---|---|---|
| 건축 덩어리 | 신전 전체가 넓은 층으로 채워짐 | 낮은 마당과 좁은 중앙 신전, 독립된 플랫폼 탑으로 분리 |
| 계단의 윤곽 | 주변 지붕이 계단·플랫폼을 가림 | 기존 디딤판 아래에 얇은 석재 구조와 독립 지지 기둥을 제작 |
| 외벽 | 기둥이 반복되는 건물 외곽 | 닫힌 석조 외벽, 중앙 문, 기존 모서리 진입로를 감싸는 문탑 |
| 회랑 | 벽 앞에 기둥을 붙인 형태 | 플랫폼 아래에 후퇴한 내실과 실제 빈 공간이 있는 회랑. 외곽 회랑은 안쪽 남북 구간에 한정 |
| 재질·장식 | 균일한 표면과 단순한 장식 띠 | Blender에서 부조·청록색 프리즈·모서리 베벨·외벽의 패인 돌을 제작. Cycles에서 석재 표면 정보를 베이크해 Unity 재질에 사용 |
| 지면과의 연결 | 깨끗한 건물 하단과 흩어진 소품 | 외벽 안팎의 낮은 모래 퇴적, 부서진 석재가 모인 잔해 추가 |

원본 플랫폼의 높이와 배치는 유지했다. 따라서 컨셉의 길쭉한 성역과 낮은 중앙부 비례까지 그대로 복제한 모델은 아니다. 컨셉에는 손으로 조각한 듯한 다양한 손상과 독자적인 문양이 더 많으며, 이 구현은 반복 가능한 게임용 석재·부조 모듈을 사용한다.

## 단계별 실제 Unity 촬영

- `01-massing-overview.png`, `01-massing-top.png`: 마당을 비우고 독립된 탑으로 나눈 첫 단계.
- `02-stonework-overview.png`, `02-stonework-interior.png`: 플랫폼 아래 회랑, 석재 표면, 모래 퇴적을 추가한 두 번째 단계.
- `03-final-overview.png`, `03-final-interior.png`, `03-final-gate.png`, `03-final-top.png`: 기울어진 문탑에 부조를 맞추고 잔해를 정리한 최종 단계.
- `03-final-in-level.png`: 모래폭풍을 포함한 실제 레벨 전경.

모든 전경은 이전 V1과 같은 카메라 위치·목표·정사영 크기와 조명을 사용해 형태를 비교했다. `in-level`을 제외한 촬영에서는 모래폭풍 렌더러를 잠시 숨겼으며, 저장된 씬에는 폭풍이 켜져 있다. 원경 촬영 중에만 그림자 거리를 600m로 늘렸다가 종료 전에 복원한다. 공유 렌더링 설정 파일을 변경하지 않는다.

## 보존 및 충돌 검증

- 원본 플랫폼 17개와 디딤판·계단 몸체·난간을 포함한 **83개 메시 참조 및 월드 변환**을 원본 씬과 직접 비교한다.
- 원래 발판·디딤판·난간 61개의 시각 형상을 유지한다. 원래의 땅까지 꽉 찬 계단 몸체는 렌더링을 끄고, Blender에서 만든 얇은 하부 구조와 지지 기둥으로 교체했다.
- 기존 단일 충돌체에는 제거한 피라미드 전체가 포함돼 있으므로 **이 복사 씬에서는 비활성화**했다. 원본 발판·디딤판의 정확한 메시로 보행 충돌체를 만들고, 난간은 별도 충돌체로 보존했다. 난간과 발판이 겹치는 원래 접합부 때문에 두 종류를 구분해 검사한다.
- 새 기단·문탑·벽·구조 기둥에는 새 형상에 맞는 MeshCollider가 있다. 부조, 모래 퇴적, 장식과 잔해에는 충돌체가 없다.
- 원본 보행면 삼각형 중심 **13,038곳**에서 보행 충돌체의 위치와 새 구조물의 침범을 검사한다.
- 마당 네 지점에서 실제 물리 레이캐스트를 수행해 제거된 피라미드가 보이지 않는 충돌체로 남아 있지 않은지 검사한다.
- 실행 결과는 `validation-03-final.txt`에 있다. 전체 전투 플레이, 캐릭터 캡슐 이동, 성능 및 LOD 검증을 대신하는 검사는 아니다.

## Blender 제작 데이터

`Temple_Courtyard_v2.blend`에는 편집 가능한 구조 메시·부조와 베이크 텍스처를 포함한 재질이 들어 있다. `REFERENCE - original decks and treads - locked` 컬렉션에는 원래 플랫폼과 디딤판이 잠긴 참조로 들어 있다. 이 참조 컬렉션은 FBX 내보내기 대상이 아니다.

`StoneBake.blend`는 석재 표면 정보를 만드는 별도 베이크 씬이다. `StoneWeather.png`의 RGB 채널은 서로 다른 크기의 얼룩·요철·입자를 담는다. 4차원 노이즈를 주기적인 좌표에 매핑해 반복 가능한 텍스처를 만들고, Unity에서 색 변화와 표면 법선에 사용한다. 모래는 프로젝트에 있던 `Sand_BaseColor.png`를 사용한다.

재생성 순서:

1. Blender에서 `Tools/Art/bake_temple_stone.py` 실행 — 석재 표면 데이터 베이크.
2. Blender에서 `Tools/Art/build_temple_architecture_v2.py` 실행 — 실제 건축 메시와 FBX 생성.
3. Unity에서 `-batchmode -executeMethod TempleCourtyardBuilder.Build -courtyardStage 이름` 실행 — 적용, 검증, 프리팹 저장, 해당 이름의 촬영 생성.

이 도구는 전용 적용 씬의 생성 건축물과 재질을 갱신한다. 적용 씬을 수동으로 수정했다면 재생성 전에 해당 변경을 보존해야 한다. 원본 게임 플랫폼이 바뀐 경우에는 `structure-reference.json`도 새 원본에 맞춰 다시 추출해야 한다.
