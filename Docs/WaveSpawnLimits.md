# 웨이브 스폰 제한과 풀 준비

`WaveDirector` 인스펙터의 **스폰 부하 제한**에서 조정한다. 기존 WaveSet의 그룹별 총수, 시작 지연, 생성 간격은 그대로 사용한다.

| 설정 | 기본값 | 의미 |
|---|---:|---|
| maxAliveEnemies | 100 | 디렉터가 집계하는 동시 생존 적 상한 |
| maxActiveEnemies | 120 | 사용하는 풀의 활성 개체 상한. 사망 연출 중인 적도 포함 |
| maxSpawnsPerFrame | 2 | 모든 스폰 그룹을 합한 프레임당 생성/대여 상한 |
| prewarmPool | true | 매 웨이브 준비 중 비활성 개체를 사전 생성 |
| prewarmPerFrame | 2 | 프레임당 사전 생성 개체 수 |

상한에 도달하면 대기 중인 스폰 수를 유지한다. 살아 있는 적이 죽고 활성 개체 여유도 생기면 원래 그룹의 남은 스폰을 이어 간다. 여러 그룹이 동시에 기다려도 디렉터의 공통 제한을 넘지 않는다. 150~200마리 웨이브를 설정해도 동시 생존 수는 기본 100을 넘지 않는다. 상한이 다른 경우 두 제한을 모두 만족해야 한다.

준비 대상은 해당 웨이브의 유효한 적 프리팹이다. 사전 준비 개체 수는 웨이브 수요와 생존/활성 상한 중 작은 수까지이며 여러 종류에 돌아가며 배분한다. 이미 풀에 있거나 사망 연출 후 반환될 개체도 포함해 중복 사전 생성을 피한다. 준비 시간 건너뛰기는 풀 준비를 생략하지 않는다. **비활성 Instantiate를 분산하는 기능**이며 첫 활성화 시 Awake, 외형 구성, 이펙트 등의 비용까지 완전히 없애는 것은 아니다.

활성 상한은 비활성 보관 개체를 포함하지 않는다. 여러 웨이브에서 종류가 바뀌면 종류별 예비 개체가 누적될 수 있다. 전체 풀 메모리 상한이나 자동 축소는 별도 기능이다. 풀 `ActiveCount`는 생존/사망 연출 중 대여 개체, `AvailableCount(prefab)`는 비활성 예비 수를 나타낸다. `CreatedCount`는 사전 생성을 포함하고 `ReusedCount`는 실제로 이전에 대여했던 개체의 재대여만 센다.

일반 `EnemyPool.Rent`는 기존 호출과 호환되도록 기본 제한이 없으며 WaveDirector가 활성 상한을 전달한다. 따라서 독립적인 부하 테스트의 150/200마리 생성은 제한하지 않는다. WaveDirector를 거치지 않는 다른 스포너에는 생존 상한이 자동 적용되지 않는다.

플레이 모드 검증: 비활성 사전 준비/건너뛰기 대기, 여러 그룹의 공통 제한과 시체 슬롯/대기 수 보존/최종 승리, 기존 2개 웨이브의 풀 재사용 동작. `Logs/WaveCapacity-results.xml`: 3개 테스트 통과.
